# KekBot v0.1.0-beta.1

**Preparation candidate — not published.** This page is the proposed first-beta release note and verification record. The beta is for evaluation; it is not stable acceptance. Start with the [beta walkthrough](../BETA.md), or return to the [documentation index](../README.md).

## Included in this beta

- Local owner setup, Argon2id accounts, invitations, roles/capabilities, revocable sessions and an authenticated dashboard.
- Kick commands, aliases, restrictions, cooldowns, timers, signed intake, durable work and connection repair.
- Optional Discord moderator controls and explicit notification routing using signed, deferred interactions.
- Alerts, local assets, themes and 18 scoped OBS widget families.
- Optional YouTube metadata validation, request/approval queue, visible embedded playback and one active player lease.
- Automated moderation, notes, safe rule tests and incident controls; points/rewards, polls, raffles and observed analytics.
- Retention/erasure, versioned configuration import/export, database/asset backup, owner recovery and a guided Linux install/update/rollback/uninstall tool.
- The final development-candidate fixes for stale Kick grants, configuration versions, paginated waiting queues, privacy associations and throttled utility errors.

See the [changelog](../../CHANGELOG.md) for development history and the [user guide](../USER_GUIDE.md) for behavior. Optional integrations remain disabled until configured by the owner.

## Distribution and requirements

Planned published assets are one audited source archive, one Linux amd64 Docker image archive, application dependency notices, `release.json` and `SHA256SUMS`. They identify the exact source and image; GitHub's automatic zip/tar is not an installer bundle. No tag, GitHub release or registry image is published by this preparation PR.

Managed installation targets Linux x86-64 with Python 3.10+, Git, Docker Engine and Compose v2. Ubuntu 24.04 is the automated CI platform. Source development uses Node 24.21.0 and pnpm 10.26.0. Windows/macOS evaluation uses Linux containers through the documented Docker Desktop path; native management and ARM64 distribution are not supported. The 2 vCPU / 2 GiB runtime target still requires reference-host measurements. Source builds need additional resources.

One installation serves one creator, with SQLite on local persistent storage and one application runtime. Live provider callbacks need publicly trusted HTTPS and owner-supplied provider applications. The project provides no hosted relay, mandatory project account or default live password.

## Compatibility and upgrades

Application version is `0.1.0-beta.1`; SQLite schema **3**, backup format **1**, configuration format **1**, release metadata **1** and host management format **1**. Application dependencies, SQL and data formats are unchanged from the final development candidate. Both image stages use official Node 24.21.0 on Debian 13 slim. The runtime applies available Debian security updates and omits unused npm/Corepack/Yarn tools; the proxy selects fixed zlib `1.3.2-r1`. Build tooling remains intact. These image changes require their own verification and do not waive remaining scanner findings. Schemas 1/2 upgrade through the existing checked-in migrations; unsupported downgrades fail. Use the schema-3-capable host tool and preserve the old image, separate encryption key and independent backup.

Updates are deliberate operator actions. Select the exact beta explicitly; **Latest stable** remains fail-closed until an accepted stable v1-or-later release exists. A source rebuild creates a separately verifiable image. Failed updates require recovery rather than ordinary Start. Media preserves the current item and queue across restart, pauses, and requires moderator resume from the item's beginning.

Read [updating](../UPDATING.md), [backup/recovery](../BACKUP_RECOVERY.md) and [uninstalling](../UNINSTALLING.md) before changing an existing installation. Pre-release API/UI behavior may evolve; compatibility beyond the declared formats is not promised.

## Known limits and remaining acceptance

- Full-product live Kick → Discord → OBS sessions, current sender identity, consent/revocation, actual YouTube embedding/audio/autoplay and provider failures remain unverified on this candidate.
- Public certificate renewal, physical host failures, another-host restoration, two independent owners and three unaided installers remain pending. The previous foundation droplet was destroyed; this PR provisions no replacement.
- Hosted fixture load shares resources with its driver/browsers. It cannot pass the reference-host benchmark or real provider latency gates.
- The [image dependency review](../RELEASE_READINESS.md#beta-dependency-review) fails on residual OS and proxy module entries. Available fixes have been applied without exclusions; image assets were withheld. Final binary license/redistribution review remains pending.
- Viewer totals are observed/estimated as documented. Unknown deliveries require reconciliation; a player error/disconnect never silently advances the queue.
- ARM64, TTS, clipping, scene control, additional streaming platforms and executable extensions remain later scope. Multi-creator/hosted operation needs a separate specification.

The [33 stable live/reference/operator gates](../release-evidence.json) remain pending. Candidate dependency/license reviews are recorded separately from stable sign-off. See [release readiness](../RELEASE_READINESS.md), [live acceptance](../LIVE_ACCEPTANCE.md) and the record below.
