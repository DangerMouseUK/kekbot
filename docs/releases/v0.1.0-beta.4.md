## Included in this beta

- A short download-and-run entry with plain-English consent before downloaded official-project management code executes. Downloads remain pinned to the resolved source SHA.
- **Recommended setup** fills standard host settings, uses a verified published image and explains live versus demo operation. Stable is preferred; only a confirmed absence of stable can offer a separately declined-by-default beta. Final `APPLY` remains required.
- **Advanced setup** retains custom directories, ports, HTTPS choices, source builds, releases, branches, PR heads, exact commits and audited local bundles. Advanced/development selections retain exact-source trust.
- A beginner server-to-dashboard walkthrough, glossary and refreshed README, documentation hub, operator, contributor and recovery guides.
- Existing status/start/stop, update, rollback and retained-data uninstall tools, with private state, backup checkpoints and incomplete-operation guards preserved. Optional Ubuntu prerequisite setup still needs separate consent.
- Disposable CI registry-cache configuration preserving every base-image digest, plus opt-in diagnostics restricted to the six public proxy files. Operator Docker settings are unchanged.

Application features remain the Kick, Discord, OBS, YouTube, moderation and community workflows in the [user guide](../USER_GUIDE.md). Beta 4 adds no application dependency, SQL migration, data-format change or new provider capability.

## Compatibility and upgrades

Distribution remains a **Linux amd64 Docker image archive** or an **audited source archive built with Docker**. Host management uses Bash and Python 3.10+ standard library. Windows/macOS can evaluate Linux containers through [Docker Desktop](../DOCKER_DESKTOP.md). There is no native executable, ARM64 package, `.deb`/`.rpm` or registry image.

SQLite remains schema 3; backup and configuration formats remain 1. Schemas 1/2 migrate as before; downgrades do not reverse migrations. Keep the original encryption key and an independent database/asset backup. Source builds have their own image identity.

**Before publication:** beta 4 cannot be selected as a release tag. Use only the full frozen SHA and complete audited bundle recorded below, following [candidate evaluation](../BETA.md#evaluate-another-reviewed-candidate). Do not substitute beta 3's image or sign-off. Keep first-time users on the [recommended walkthrough](../GETTING_STARTED.md), which offers actual published versions only.

**After publication:** the same walkthrough can offer beta 4 explicitly. To pin both released management and application code, download and [verify the complete versioned bundle](../LAUNCHER.md#verify-a-versioned-launcher-download), then run from its directory in Bash on a supported host:

```sh
sudo bash install.sh install --tool-release v0.1.0-beta.4 --release v0.1.0-beta.4 --format image
```

Choose a separate demo or a live installation, review the settings and type `APPLY`. The explicit tag selects a beta deliberately; strict `--stable` never selects it. Advanced source builds may require exact-source trust.

For an older wizard-managed beta installation, use that separately reviewed beta 4 launcher to update the application:

```sh
sudo bash install.sh update --root /srv/kekbot --tool-release v0.1.0-beta.4 --release v0.1.0-beta.4 --format image
```

Replace the root with your actual root. **Application updates do not replace copied management tools.** Keep the reviewed beta 4 launcher/tool source for later operations; older installations retain their original menus and may lack `/tool/install.sh`. Do not copy files over the installed manager. Check readiness, sign-in, accounts, connections, assets and queue before resuming media. Follow [updating/recovery](../UPDATING.md); never bypass a failed-operation guard. [Uninstall](../UNINSTALLING.md) retains data unless you separately confirm purge.
