## Changes from beta 1

The bundled domain/IP HTTPS installer now stages the locked Caddy Go sources at the Dockerfile's required `deploy/caddy/` paths. It retains the Dockerfile, both configurations and Go sources with the copied management tool. Fresh installations can use the beta 2 tool and application from the same release; beta 1's separate fixed-tool workaround is unnecessary for beta 2.

Regression tests cover both HTTPS modes, retained resources after the original checkout is unavailable, and missing inputs failing before installation state is created. Linux CI builds Caddy from the actual retained/staged context and adapts domain/IP configurations without requesting certificates. A whole-checkout build or loopback fixture alone cannot establish this behavior.

README, installation, beta, update, API, contributor and release guidance now follow beta 2. No application feature, production dependency, SQL migration or data format changed from beta 1. New version/source labels produce separately reviewed artifacts; beta 1's tag and downloads are not replaced.

## Included in this beta

The existing product includes local accounts and delegated permissions; Kick commands, timers and connection controls; Discord notifications and moderator controls; alerts, local assets and OBS sources; YouTube request/approval/playback and durable queue controls; moderation; points/rewards, polls and raffles; analytics/privacy; configuration portability; backup/recovery; and guided install/update/rollback/uninstall.

Follow [first session](../FIRST_SESSION.md), [the user guide](../USER_GUIDE.md), [provider setup](../PROVIDERS.md) and [OBS/media](../OBS.md). Discord and YouTube remain optional to enable. Begin with isolated fixtures; enabled live integrations use owner-controlled applications and consent.

## Compatibility and upgrades

Application `0.1.0-beta.2`; SQLite schema **3**, backup/configuration formats **1**, release metadata **1**, host management format **1**. Supported prebuilt format: Linux amd64 Docker image archive, plus audited source and notices archives. Node/pnpm remain 24.21.0 / 10.26.0; the non-root shell-free runtime and locked Caddy 2.11.6 build are unchanged. Native Windows/macOS installers, ARM64 and registry images are not offered. See [runtime compatibility](../RUNTIME_IMAGE.md).

For a new install, pin the beta 2 tag, review its tool and select **Specific release** → `v0.1.0-beta.2`. The [beta walkthrough](../BETA.md#install-the-published-beta) explains checksums, trust confirmation and fixture/live choices. Latest stable excludes prereleases.

For beta 1, follow [upgrading the beta](../BETA.md#update-recover-or-remove) with the reviewed beta 2 tool checkout and an independent database/asset backup plus original encryption key. Application updates do not replace the copied host tool; keep the pinned beta 2 checkout for subsequent management. Failed updates require recovery; media remains paused after restart until moderator resume. Existing checked-in migrations support schemas 1/2 → 3; there is no downgrade SQL.

## Known limits

- Full-product live Kick → Discord → OBS sessions, real YouTube audio/embedding/autoplay and provider failure/revocation checks remain pending.
- Public certificate issuance/renewal, reference-host performance and physical failures, another-host restoration, independent owners and unaided installers still need live evidence. No replacement host is provisioned by this release.
- Node amd64 musl support remains upstream experimental. Functional container evidence does not establish reference-host performance. The earlier hosted one-hour soak belongs to its original source, not this image.
- Raw tooling/proxy advisory counts and any exact verified remediation remain in [the candidate review](../RELEASE_READINESS.md#beta-2-review); no blanket exclusions or affected-code waivers are permitted.
- ARM64, TTS, clipping, scene control, additional streaming platforms and executable extensions remain later scope. Multi-creator/hosted operation needs a separate specification.

All 33 live/reference/operator gates in [release-evidence.json](../release-evidence.json) remain pending. This is evaluation distribution, not stable acceptance.
