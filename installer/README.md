# Host lifecycle tooling

Operator walkthrough: [guided installer](../docs/INSTALLER.md), [updates](../docs/UPDATING.md), [uninstall](../docs/UNINSTALLING.md). Run `python3 -B installer/kekbot.py --help` from the source root. This is a Linux x86-64 interactive host tool, not an HTTP API or application-container command.

The root [`install.sh`](../install.sh) provides the [downloadable entry](../docs/LAUNCHER.md). Bash owns argument/host checks, separately confirmed Ubuntu prerequisite assistance, pinned allowlisted management staging, tool trust and dispatch. Python retains every application/lifecycle decision. Default new-tool source is `main`; default application source remains accepted latest stable. Routine management reuses protected copied tools without downloading code. New tool downloads require exact-SHA trust, local tools require explicit local trust, and installed tools require protected root-owned paths. Keep those identities separate from application source/image selection.

Published beta 3 packages include a checksum-covered standalone `install.sh`, identical to both the committed file and archived source. Release metadata 1 gains an optional `launcher` field; the existing release/bundle resolver remains compatible with beta 1/2 bundles without it. Asset verification never executes downloaded management code. Review/pin bootstrap, management SHA and application identity independently; [versioned download instructions](../docs/LAUNCHER.md#verify-a-versioned-launcher-download) cover actual released assets and separately reviewed candidates.

`test_launcher.py` covers Bash syntax/help, selector/quoting policy, failed transport, exact identity, missing/link/submodule staging, prerequisite guards and Python source prefill. Linux additionally uses a real pseudo-terminal for consent/cancellation and offline installed dispatch. `smoke.py` installs the real audited image through the launcher and Python wizard, verifies the launcher is retained, then uses it for status/stop/start before the existing recovery/removal rehearsal. Terminal output is bounded/discarded; raw transcripts/credentials are never published. Fresh-host apt installation and unaided operators remain separate trials.

The rehearsal derives application trust input from the verified bundle's `accepted` flag: candidate bundles need `TRUST <SHA>` before `APPLY`, while acceptance-verified bundles go directly to `APPLY`. An offline regression feeds both generated sequences through the real installation prompts/confirmations, isolating host effects, and checks installation occurs with no unused input. Synthetic accepted metadata tests prompt compatibility; it does not pass stable release gates.

The [beta walkthrough](../docs/BETA.md) explains explicit selection of the published beta. Offline contracts cover an unaccepted beta through both source/image release assets and reject it through latest-stable selection before downloading. Linux CI rehearses the actual exported candidate bundle and can select an explicit published release through real discovery. Its [dated distribution outcomes](../docs/releases/v0.1.0-beta.3.md#published-distribution-checks) remain separate from an unaided independent installer trial.

`kekbot.py` owns explained menus, defaults, cancellation and typed final confirmation. `core.py` owns source resolution, verified bundle extraction, immutable image/Compose state and locked lifecycle transactions. It uses Python 3.10+ standard library only so a Docker host does not need Node/pnpm/pip. Do not add provider credentials to terminal prompts or execute downloaded management code implicitly.

`test_lifecycle.py` and `test_launcher.py` run offline with `pnpm test:installer` (included in `pnpm check`). Portable contract tests run on Windows with Git for Windows Bash; Linux additionally tests terminals, locks, interrupted updates, checkpoints, rollback and removal boundaries. `smoke.py` is CI-only, run with sudo **after** candidate package checksums: launcher → real audited image → isolated fixture installation/signed event → deliberately broken maintenance image → failed update → new-root rollback → verified source-bundle build → successful update → retained-data removal/resume → explicit purge. It never installs host packages, uses live providers/public TLS or uploads runtime artifacts.

`smoke.py --release v0.1.0-beta.2` exercises actual public release discovery, checksums and both formats through that same isolated lifecycle. The [published beta 2 rehearsal](../docs/releases/v0.1.0-beta.2.md#verification-record) passed. The optional CI `published_release` input supplies the tag through a quoted environment variable. It uses the installed repository host tool; downloaded management code is not adopted or executed implicitly. Source/image selections must agree. This is automated distribution evidence, separate from an unaided operator trial. Its fixture topology uses loopback without bundled HTTPS; the retained/staged proxy build is a separate check and does not prove public certificate issuance/renewal.

`python3 -B installer/smoke.py --proxy-context`, from the repository root on Linux with Docker access, separately copies only the retained proxy resources, stages their real Docker context, builds Caddy and adapts domain/IP configurations. It does not request certificates or start an application. Ordinary container CI runs it before application checks. `PROXY_FILES` allowlists the Dockerfile, both configurations and locked `caddy/go.mod`, `caddy/go.sum`, `caddy/main.go`; staging preserves the `deploy/caddy/` paths consumed by Docker. Portable tests cover the actual domain/IP install calls, all retained resources and failure before creating the root when an input is missing. The [beta 1 workaround](../docs/INSTALLER.md#beta-1-bundled-https-installer-fix) distinguishes the fixed tool from immutable published assets.

Management record/Compose/environment are private, outside source. Installation record format 1 carries active immutable image, mode/origin/project/data root, selected source identity and one previous checkpoint. Update phases are persisted before migration; rollback restores into a new root, never runs older code against mutated storage. Extend format compatibility deliberately and update guides/tests; do not silently adopt arbitrary manual deployments.

Fresh installations prepare and inspect the proxy before creating the managed root/record, so a failed Caddy build can retry without stranded state. Install/update/rollback attempt shutdown in `finally` even if recording failure fails; failed final activation writes receive the same cleanup. Retained uninstall preserves incomplete operation statuses and checkpoints rather than making failed storage eligible for Start/Update. Portable failure regressions use real private records and simulated Docker; Linux also uses actual locks and the container rehearsal.

Start now uses the same independent shutdown path for readiness and final-save failures. The Linux smoke rehearsal checks that no managed services remain running in both cases. Current reviewed tooling accepts bundle metadata 1 with schemas 2 or 3 and backup format 1; application updates do not silently replace older management tools.

`--diagnostics-dir` enables private metadata logs outside source. They contain UTC time, operation class, outcome, elapsed milliseconds and exit code only. They exclude arguments, paths, environment and subprocess output. A private directory and non-linked files are required; rotation bounds storage to approximately three 1 MiB files. Logging failures cannot interrupt lifecycle cleanup. See [the operator walkthrough](../docs/INSTALLER.md#optional-private-diagnostics).

Root/Docker privileges and selected branch/PR builds require reviewed source. Reject shell interpolation, unsafe archives, links and path escapes. Suppress raw subprocess output; operator-visible failures must not print environment/body/credential values. Uninstall defaults to retaining data, and purge is scoped to the exclusively managed root and named project volumes. Never introduce global Docker prune or automatic infrastructure/provider changes.
